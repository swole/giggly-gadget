# Giggly Gadget - feature map (how to reach and verify every feature)

AGENTS.md says how the code works. This file says how an agent *drives* the app and what each page must show, so a report like "the pills aren't showing on the plan page" can be reproduced without Johnny checking on his phone. Keep it current: when a page, tab, chip or role rule changes, change its row here in the same commit (the tests gate the deploy; this file gates the verification).

## Drive it
- **Dev server:** Browser pane -> `preview_start {name: "giggly-gadget"}` (launch config in `9. Claude/.claude/launch.json`, port 3010, autoPort), or `npm run dev` in `C:/Users/johnn/code/giggly-gadget`.
- **Dev = production data.** `.env.local` (from `vercel env pull`) points at the prod Supabase and Notion. Never fill, randomize or clear the *current* or *next* week while verifying. Use a **sandbox week**: any Monday at least 8 weeks out, `/plan?week=YYYY-MM-DD`. Clear it when done (Week actions -> Clear the week, or `POST /api/plan/clear {week_of}`).
- **Phone width first:** `resize_window {width: 390, height: 844}`. Every page is designed at 390; desktop width hides nothing but is not what the household sees.
- **Role, no login.** First load shows the RoleSheet ("Who is using this phone?") with Johnny / Lydia / Shallaine. Set it directly from `javascript_tool`: `await fetch('/api/role', {method:'POST', headers:{'content-type':'application/json'}, body: JSON.stringify({role:'johnny'})})` then reload. Roles: `johnny | lydia | helper`. `?as=helper` on any URL picks helper for a cookie-less browser. Switch via the tab-bar button (aria-label "Signed in as <Name>. Switch person."). `DELETE /api/role` clears.
- **Tab bar** (nav aria-label "Primary"): planners see Kitchen · Plan · Grocery · Recipes · Add; helper sees Kitchen · Grocery · Recipes. No tab bar in cook mode or before a role is picked.
- **Number keys drive the bar** (laptop only): the digit is the item's position, so `1`-`5` are the planner's tabs and `6` is the person button; the helper gets `1`-`3` and `4`. `?` opens the shortcuts card (heading "Keyboard", `data-hotkeys="passthrough"` so a digit pressed on it still navigates), `Esc` closes any sheet including the person switcher. Ignored while typing, while another sheet is open, with Ctrl/Cmd/Alt held, and in cook mode. The digits render as `.kbd-hint` spans beside the labels, `display:none` unless `(hover: hover) and (pointer: fine)` - so a phone or tablet sees the bar exactly as before. **Verifying:** the Browser pane silently drops key presses until the tab has been screenshotted since its last full load - take a screenshot first, then send keys, or a working hotkey looks broken.
- **Read, don't screenshot:** `read_page` / `find` on the labels below; screenshot only as proof at the end. `read_console_messages` after every page load.
- **Realtime:** plan and grocery changes propagate between tabs (Supabase Realtime). A second Browser-pane tab is how "shows up on the other phone" is verified.

## API surface for verification (planner cookie where marked)
`GET /api/plan/meals?week=YYYY-MM-DD` -> `{week_of, meals, lunch, trips}` · `PATCH /api/plan/meals/<id> {planned_for, slot, position}` (a move; 409 `{error, reason}` when the recipe is already there or leftovers would land at or before their meal) · `POST /api/plan/trips {person, from_date, from_slot, to_date, to_slot}` -> `{trip}` (planner) · `PATCH|DELETE /api/plan/trips/<id>` (planner) · `POST /api/plan/randomize {week_of, days?, slots?, mode: "fill_empty"|"replace", replace_ids?, include_sunday?}` (planner) · `POST /api/plan/clear {week_of}` (planner) · `PUT /api/plan/lunch {planned_for, person: "johnny"|"lydia", location: "home"|"office"}` (planner) · `GET /api/recipes/<id>/ingredients` (check `scalable`) · `GET /api/sync-now?force=0&cb=<n>` -> `{upserted, errors, lint}` · `GET /api/sync-stats` · `GET /api/spend?week=YYYY-MM-DD` -> `{week_of, expenses, owed}` · `POST /api/spend {week_of, shop, total_cents, paid_with, spent_on, items?}` (any role) · `PATCH|DELETE /api/spend/<id>` · `PUT /api/spend/reimburse {ids, undo?}` (planner) · `POST /api/spend/read-receipt {photos, week_of, shop}` (any role, spends Claude, capped at 12 reads per 24 h) · `GET /api/spend/export?from&to` (planner, CSV).

## Report -> reproduction (the "Benny" loop)
1. `preview_start giggly-gadget`; role via `/api/role`; 390 px; `read_console_messages`.
2. Find the row above; go to the route; `find` the control by its label or aria-label.
3. If it is missing: readiness probes first (`lunchLocationsReady` -> does `lunch_locations` exist in Supabase?), then the console, then the network (`read_network_requests`).
4. Report: reproduces on dev yes/no · already fixed on main yes/no · exact page and label looked for · one screenshot as proof.

## Known non-features (don't chase)
- Kitchen only shows this week; planning a sandbox week never changes it.
- iOS has no share-sheet path into the PWA; the Paste button is the iOS route. Instagram/Facebook links cannot be read by `/add` (paste the caption).
- Recent one-off chips left the picker 2026-08-30; the <= 30 min chip left it 2026-09-05 (it lives in Discover's Filters and the RandomizeSheet).
